== Overview

This extension adds a new set of types known as "cooperative matrix" types,
where the load/store operations and computations performed on such matrix types are spread
across a set of invocations such as a subgroup. These types give the
implementation freedom in how to optimize matrix multiply operations.

This extension introduces limited support for parameterized types,
utilizing the added attribute specifier `coop_mat`.

== Modifications to the OpenCL C Specification

=== (Add a new Section 6.3.X, *Cooperative Matrix Type*) :

Cooperative matrix types are types where the load/store operations and
computations that are performed on the matrix elements are spread across a set of
invocations such as a subgroup. These types give the implementation
freedom in how to optimize matrix multiply operations.

Cooperative matrices are supported in the language by applying the
`coop_mat` attribute specifier to the base component type.
The `coop_mat` specifier is parameterized by four parameters:
scope, rows, columns, and use.

The base component type must be a scalar numerical type.

The scope parameter must be one of the supported memory scopes as
defined in the 'Memory Scope' section.

The rows and columns parameters must be constant expressions,
and no error checking is performed on their values at compile time.

The use parameter must be one of the following predefined enums:

[width="100%",options="header"]
|====
| value

| `CLK_COOPERATIVE_MATRIX_A`

| `CLK_COOPERATIVE_MATRIX_B`

| `CLK_COOPERATIVE_MATRIX_ACCUMULATOR`

|====

The use parameter controls which operand of **coop_mat_mulAdd** the
type can be used as.


Cooperative matrix types can be used as local variables, function parameters,
and function return values.
They must not be used as kernel arguments.

Examples of cooperative matrix declarations:

[source,c]
----
float vmat1 __attribute__((coop_mat(CLK_COOPERATIVE_MATRIX_SCOPE_SUBGROUP, 8, 8, CLK_COOPERATIVE_MATRIX_A)));


typedef half chmat44 __attribute__((coop_mat(CLK_COOPERATIVE_MATRIX_SCOPE_SUBGROUP, 4, 4, CLK_COOPERATIVE_MATRIX_B)));
chmat44 vmat2;

----


=== (Add to Section 6.4.1. *Implicit Conversions*) :

Implicit conversions between cooperative matrix types are disallowed.

=== (Add to Section 6.4.2. *Explicit Casts*) :

Explicit casts between cooperative matrix types are disallowed.

=== (Add to Section 6.4.3. *Explicit Conversions*) :

Conversions are allowed between cooperative matrix type only if
the scope, row, column, and use parameters are the same.


=== (Add a new Section 6.5.X, *Cooperative Matrix Operators*) :

The arithmetic binary operators add (+), subtract (-), multiply (*), and
divide (/) operate on cooperative matrix types and perform the operation
component-wise. The operands must have identical types.

The arithmetic binary operator multiply (*) also operates on a cooperative
matrix type and a scalar (in either order) and performs the multiply operation
component-wise. The scalar type must match the component type of the
matrix.

The arithmetic unary operator negate (-) operates on cooperative matrix
types and performs the operation component-wise.

The components of a cooperative matrix are spread across the invocations
in its scope, in an implementation-dependent manner. The components owned
by a given invocation can be accessed using array subscripting syntax,
and the number of components owned by each invocation can be queried
using the **coop_mat_length** function. The type returned by **coop_mat_length** is `uint`.
There is no compile-time bounds checking of array indices.

This can be used, for example, to perform component-wise operations on
all components of a cooperative matrix:


[source,c]
----
float m __attribute__((coop_mat(CLK_COOPERATIVE_MATRIX_SCOPE_SUBGROUP, 16, 8, CLK_COOPERATIVE_MATRIX_A)));

...
for (int i = 0; i < coop_mat_length(m); ++i) {
	m[i] = f(m[i]);
}
----

=== (Add to Section 6.5.11. *Sizeof Operator*) :

When the *sizeof* operator is applied to a cooperative matrix type,
the result is the total size (in bytes) of the cooperative matrix across all invocations in its scope.
The result is implementation-defined.

=== (Add to Section 6.7.7. *Initialization*)

Cooperative matrices can be initialized using a single scalar value as follows:

[source,c]
----
float vmat1 attribute((coop_mat(CLK_COOPERATIVE_MATRIX_SCOPE_SUBGROUP, 8, 8, CLK_COOPERATIVE_MATRIX_A)));
vmat1 = coop_mat_init(0.0);
----

The single scalar value can be any given value (constant or variable) as cooperative matrices
can be defined in private address space. Type of the scalar value should match the base
component type of the cooperative matrix, and all components of the matrix are initialized to
that value.

=== (Add to Section 6.11. *Restrictions*) :

The following restrictions apply to cooperative matrix type:

 - Pointers to cooperative matrices are not allowed;
 - Arrays of cooperative matrices are not allowed;
 - Cooperative matrix is not allowed to be a member of a struct or union;
 - The address operator can not be applied to a cooperative matrix or an element of a cooperative matrix;
 - Cooperative matrices must not be used as kernel arguments or global variables;
 - Cooperative matrices can only be declared in the private address space.


=== (Add a new Section 6.13.X, *Specifying the Cooperative Matrix Attribute*) :


The `+__attribute__ ((coop_mat(scope, row, column, use)))+` declares a cooperative matrix type.

=== (Add a new Section 6.15.X, *Cooperative Matrix Functions*) :

The following functions are used to load and store cooperative matrix
values from and to memory. In memory, the matrices are stored as arrays
of their element type and size. In the following functions, the generic type
`coop_mat` can accept a cooperative matrix type with any type parameters.

The _p_ is a pointer to the element of the array to load from/store to.
The element type of the array can be any scalar or vector numerical type and is
indicated as `gentype`.

The _layout_ indicates the layout of the matrix values in memory. It can accept
one of the predefined enums: `CLK_COOPERATIVE_MATRIX_LAYOUT_ROW_MAJOR` or
`CLK_COOPERATIVE_MATRIX_LAYOUT_COLUMN_MAJOR`

For all of these functions, for a given dynamic instance of the function
call, all function parameters must be the same for all invocations in a
given scope instance (where the scope is the scope the cooperative matrix
type(s) were created with). All invocations in a given scope instance must
be active or all must be inactive.

[[table-coopmat-loadstore]]
.Cooperative Matrix Load and Store Functions
[cols="7,3",options="header",]
|====
| Function | Description
| coop_mat **coop_mat_load**(const gentype *_p_, const coop_matrix_layout_t _layout_, const size_t _stride_)
 | Load a cooperative matrix from _p_. +
   If _layout_ is `CLK_COOPERATIVE_MATRIX_LAYOUT_ROW_MAJOR`,
   then elements (row,\*) of the result are taken in
   order from contiguous locations starting at _p_ + _row_*_stride_. +
   If _layout_ is `CLK_COOPERATIVE_MATRIX_LAYOUT_COLUMN_MAJOR`,
   then elements (*,col) of the result are taken in
   order from contiguous locations starting at _p_ + _col_*_stride_.
|  void **coop_mat_store**(const gentype *_p_, coop_mat _m_, const coop_matrix_layout_t _layout_, const size_t _stride_);
 | Store a cooperative matrix to _p_. +
   If _layout_ is `CLK_COOPERATIVE_MATRIX_LAYOUT_ROW_MAJOR`,
   then elements (row,\*) of _m_ are stored in
   order from contiguous locations starting at _p_ + _row_*_stride_. +
   If _layout_ is `CLK_COOPERATIVE_MATRIX_LAYOUT_COLUMN_MAJOR`,
   then elements (*,col) of _m_ are stored in
   order from contiguous locations starting at _p_ + _col_*_stride_.
|====
